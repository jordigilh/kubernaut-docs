# v1.0 to v1.1

Kubernaut 1.1 simplifies the Helm chart, removes the Event Exporter, migrates from Redis to Valkey, externalizes all policy and SDK configuration, and adds alert decay detection to the Effectiveness Monitor.

!!! warning "CRD schema changes"
    All five CRDs have schema updates. Apply CRDs **before** upgrading --
    see [General Upgrade Procedure](index.md#crd-schema-changes).

## Breaking Changes

### Redis replaced by Valkey

All `redis.*` Helm values have been renamed to `valkey.*`. The in-memory store is now [Valkey](https://valkey.io/) (BSD-licensed, Redis-compatible).

**Detection:** `helm upgrade` will warn about unknown values if your values file still contains `redis.*` keys.

**Remediation:** Rename `redis.*` to `valkey.*` in your values file.

| v1.0 value | v1.1 equivalent |
|---|---|
| `redis.enabled` | `valkey.enabled` |
| `redis.image` | `valkey.image` (default: `valkey/valkey:8-alpine`) |
| `redis.replicas` | `valkey.replicas` |
| `redis.existingSecret` | `valkey.existingSecret` |
| `redis.password` | _(removed -- auto-generated when existingSecret is empty)_ |
| `redis.storage.*` | `valkey.storage.*` |
| `externalRedis.host` | `valkey.host` (when `valkey.enabled=false`) |
| `externalRedis.port` | `valkey.port` |
| `externalRedis.existingSecret` | `valkey.existingSecret` |
| `externalRedis.password` | _(removed)_ |

### PostgreSQL data directory changed

The PostgreSQL data directory moved from image-specific paths (`/var/lib/postgresql/data` for upstream, `/var/lib/pgsql/data` for OCP) to a single image-agnostic path: `/var/lib/kubernaut-pg/data`.

**Detection:** After upgrading, verify the PostgreSQL pod starts correctly and the workflow catalog is populated (`kubectl get rw -A`).

**Remediation:** Either:

1. Copy existing data from the old path to the new path before upgrading, or
2. Re-apply ActionType and RemediationWorkflow CRDs after upgrading to repopulate the catalog from the DataStorage registration pipeline.

### External PostgreSQL values consolidated

The `externalPostgresql.*` block has been removed. Configure external PostgreSQL directly under `postgresql.*`:

| v1.0 value | v1.1 equivalent |
|---|---|
| `externalPostgresql.host` | `postgresql.host` (when `postgresql.enabled=false`) |
| `externalPostgresql.port` | `postgresql.port` |
| `externalPostgresql.auth.*` | `postgresql.auth.*` |

### PostgreSQL variant for OCP

A new `postgresql.variant` field (`upstream` or `ocp`) replaces manual image switching. Set `postgresql.variant: ocp` for Red Hat RHEL PostgreSQL images with `POSTGRESQL_*` environment variables and restricted-v2 SCC compatibility.

### Effectiveness Monitor defaults changed

`prometheusEnabled` and `alertManagerEnabled` now default to `false`. New installs will not have Prometheus-based effectiveness assessments unless explicitly enabled. Upgraders using `--reuse-values` are unaffected (existing values are preserved).

**Detection:** After upgrading without `--reuse-values`, EffectivenessAssessments may complete with `partial` or `expired` reasons.

**Remediation:** Add to your values:

```yaml
effectivenessmonitor:
  external:
    prometheusEnabled: true
    alertManagerEnabled: true
```

### Password auto-generation

`postgresql.auth.password` and `redis.password` (now `valkey.*`) no longer accept plaintext passwords in values. Credentials are auto-generated on first install when `existingSecret` is empty and preserved on upgrade via Helm lookup. For production, pre-create a Secret and set `existingSecret`.

## New Features

- **Demo content** ([`demoContent.enabled: true`](../../getting-started/installation.md#action-types-and-workflows-demo-content)): Seeds 25 ActionTypes and 20 RemediationWorkflows for immediate evaluation. Set to `false` for production and deploy your own CRs.
- **Alert decay detection** ([DD-EM-003](../../architecture/effectiveness.md#alert-decay-detection-dd-em-003)): EM detects when Prometheus alerts persist due to lookback window rather than genuine re-occurrence.
- **Actionability classification** ([#388](../../api-reference/crds.md#aianalysisstatus)): LLM classifies benign alerts as `NotActionable`, skipping workflow selection.
- **TLS manual mode** ([`tls.mode: manual`](../../user-guide/configuration.md#tls-certificate-management)): For service meshes, external PKI, or CI environments.
- **PodDisruptionBudgets**: All controllers support [`<service>.pdb.enabled`](../../user-guide/configuration.md).
- **Unified Rego evaluator** ([ADR-060](../../user-guide/policies.md)): Single `policy.rego` replaces per-classifier Go code for signal processing.
- **SDK config externalization** ([`sdkConfigContent`](../../user-guide/configmap-holmesgpt.md)): Full control over HolmesGPT SDK configuration via `--set-file` or pre-existing ConfigMap.
- **Notification routing externalization** ([`routing.content`](../../user-guide/configmap-notification.md)): Custom notification routing via `--set-file` or pre-existing ConfigMap.
- **Slack quickstart shortcut** ([`notification.slack.secretName`](../../user-guide/configuration.md#notification)): Simplified Slack setup without a full routing config.
- **OCP and airgap overlays**: [`values-ocp.yaml`](../../getting-started/installation.md#openshift-ocp) and [`values-airgap.yaml`](../../operations/disconnected-install.md) for platform-specific deployments.
- **Workflow supersession** ([#371](../../architecture/data-persistence.md#remediation_workflows)): Only one workflow version per name can be active at a time.
- **HAPI Prometheus integration** ([`holmesgptApi.prometheus.enabled`](../../user-guide/configuration.md#holmesgpt-api)): Auto-configures the Prometheus toolset in the SDK config for LLM investigation context.
- **Proactive signal mappings** ([ADR-054](../../user-guide/policies.md)): Map proactive signal names to their reactive equivalents.

All five CRDs have schema updates. Apply CRDs before upgrading (see [General Upgrade Procedure](index.md#crd-schema-changes)).
