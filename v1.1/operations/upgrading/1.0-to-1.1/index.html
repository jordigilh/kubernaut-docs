    v1.0 to v1.1¶

    Kubernaut 1.1 simplifies the Helm chart, removes the Event Exporter, migrates from Redis to Valkey, externalizes all policy and SDK configuration, and adds alert decay detection to the Effectiveness Monitor.

    CRD schema changes

    All five CRDs have schema updates. Apply CRDs before upgrading -- see General Upgrade Procedure.

    Breaking Changes¶

    Redis replaced by Valkey¶

    All redis.* Helm values have been renamed to valkey.*. The in-memory store is now Valkey (BSD-licensed, Redis-compatible).

    Detection: helm upgrade will warn about unknown values if your values file still contains redis.* keys.

    Remediation: Rename redis.* to valkey.* in your values file.

    v1.0 value v1.1 equivalent
    redis.enabled valkey.enabled
    redis.image valkey.image (default: valkey/valkey:8-alpine)
    redis.replicas valkey.replicas
    redis.existingSecret valkey.existingSecret
    redis.password (removed -- auto-generated when existingSecret is empty)
    redis.storage.* valkey.storage.*
    externalRedis.host valkey.host (when valkey.enabled=false)
    externalRedis.port valkey.port
    externalRedis.existingSecret valkey.existingSecret
    externalRedis.password (removed)

    PostgreSQL data directory changed¶

    The PostgreSQL data directory moved from image-specific paths (/var/lib/postgresql/data for upstream, /var/lib/pgsql/data for OCP) to a single image-agnostic path: /var/lib/kubernaut-pg/data.

    Detection: After upgrading, verify the PostgreSQL pod starts correctly and the workflow catalog is populated (kubectl get rw -A).

    Remediation: Either:

    1. Copy existing data from the old path to the new path before upgrading, or
    2. Re-apply ActionType and RemediationWorkflow CRDs after upgrading to repopulate the catalog from the DataStorage registration pipeline.

    External PostgreSQL values consolidated¶

    The externalPostgresql.* block has been removed. Configure external PostgreSQL directly under postgresql.*:

    v1.0 value v1.1 equivalent
    externalPostgresql.host postgresql.host (when postgresql.enabled=false)
    externalPostgresql.port postgresql.port
    externalPostgresql.auth.* postgresql.auth.*

    PostgreSQL variant for OCP¶

    A new postgresql.variant field (upstream or ocp) replaces manual image switching. Set postgresql.variant: ocp for Red Hat RHEL PostgreSQL images with POSTGRESQL_* environment variables and restricted-v2 SCC compatibility.

    Effectiveness Monitor defaults changed¶

    prometheusEnabled and alertManagerEnabled now default to false. New installs will not have Prometheus-based effectiveness assessments unless explicitly enabled. Upgraders using --reuse-values are unaffected (existing values are preserved).

    Detection: After upgrading without --reuse-values, EffectivenessAssessments may complete with partial or expired reasons.

    Remediation: Add to your values:

    effectivenessmonitor:
  external:
    prometheusEnabled: true
    alertManagerEnabled: true

    Password auto-generation¶

    postgresql.auth.password and redis.password (now valkey.*) no longer accept plaintext passwords in values. Credentials are auto-generated on first install when existingSecret is empty and preserved on upgrade via Helm lookup. For production, pre-create a Secret and set existingSecret.

    New Features¶

    • Demo content (demoContent.enabled: true): Seeds 25 ActionTypes and 20 RemediationWorkflows for immediate evaluation. Set to false for production and deploy your own CRs.
    • Alert decay detection (DD-EM-003): EM detects when Prometheus alerts persist due to lookback window rather than genuine re-occurrence.
    • Actionability classification (#388): LLM classifies benign alerts as NotActionable, skipping workflow selection.
    • TLS manual mode (tls.mode: manual): For service meshes, external PKI, or CI environments.
    • PodDisruptionBudgets: All controllers support <service>.pdb.enabled.
    • Unified Rego evaluator (ADR-060): Single policy.rego replaces per-classifier Go code for signal processing.
    • SDK config externalization (sdkConfigContent): Full control over HolmesGPT SDK configuration via --set-file or pre-existing ConfigMap.
    • Notification routing externalization (routing.content): Custom notification routing via --set-file or pre-existing ConfigMap.
    • Slack quickstart shortcut (notification.slack.secretName): Simplified Slack setup without a full routing config.
    • OCP and airgap overlays: values-ocp.yaml and values-airgap.yaml for platform-specific deployments.
    • Workflow supersession (#371): Only one workflow version per name can be active at a time.
    • HAPI Prometheus integration (holmesgptApi.prometheus.enabled): Auto-configures the Prometheus toolset in the SDK config for LLM investigation context.
    • Proactive signal mappings (ADR-054): Map proactive signal names to their reactive equivalents.

    New Helm Values¶

    Notable additions (see Configuration Reference for the full list):

    Value Description
    demoContent.enabled Deploy demo ActionTypes and RemediationWorkflows (default: true)
    tls.mode: manual User-managed TLS certificates
    <service>.pdb.enabled PodDisruptionBudget per controller
    signalprocessing.policy Unified Rego policy content (--set-file)
    aianalysis.policies.content Approval policy content (--set-file)
    holmesgptApi.sdkConfigContent Raw SDK config YAML (--set-file)
    holmesgptApi.prometheus.enabled Auto-configure Prometheus toolset
    notification.slack.secretName Slack quickstart shortcut
    notification.routing.content Custom routing config (--set-file)
    postgresql.variant upstream or ocp
    gateway.config.* Server and deduplication settings
    datastorage.config.* Database connection pool settings
    remediationorchestrator.config.timeouts.* Per-phase timeout configuration
    remediationorchestrator.config.routing.* Consecutive failure and cooldown thresholds
    workflowexecution.config.execution.cooldownPeriod Cooldown between executions (default: 1m)
    effectivenessmonitor.config.assessment.* Stabilization and validity windows
    global.image.digest Immutable image references via SHA256 digest

    All five CRDs have schema updates. Apply CRDs before upgrading (see General Upgrade Procedure).

    WorkflowExecution Added ephemeralCredentialIDs status field (replaces annotation-based AWX credential storage)
    RemediationRequest Minor cleanup
